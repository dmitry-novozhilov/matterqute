# matterqute

Десктопный клиент Mattermost на Go и Qt6 Widgets (через MIQT).

## Стек

- Go: `go.mod` требует `go 1.26.10` — этого хочет `github.com/mattermost/mattermost/server/public` v0.6.0. Системный go 1.24 сам скачивает нужный тулчейн (`GOTOOLCHAIN=auto`).
- UI: `github.com/mappu/miqt/qt6` v0.15.0 — CGO-биндинги к Qt 6.4+ (в Debian 13 — Qt 6.8.2). Первая сборка с MIQT идёт ~10 минут (компилируются биндинги), потом быстро.
- Сервер: `model.Client4` (REST API v4) и `model.WebSocketClient` из `mattermost/server/public` (Apache-2.0).

## Сборка

Системные пакеты (Debian 13): `qt6-base-dev qt6-svg-dev qt6-image-formats-plugins qt6-multimedia-dev build-essential pkg-config`. Видео играет плагин ffmpeg из `libqt6multimedia6` (ставится вместе с `qt6-multimedia-dev`). Шрифты (IBM Plex Sans, PT Mono, Noto Color Emoji, все под OFL) зашиты в бинарник через `go:embed`, системные не нужны.

```sh
go build ./cmd/matterqute
go test ./...
./matterqute --install    # ярлык в меню и иконки (~/.local/share): счётчик в доке, ссылки mattermost:// из браузера
./matterqute mattermost://mm.example.com/team/pl/<id>   # открыть ссылку (запущенное приложение откроет её само)
./matterqute --uninstall
```

Тесты `internal/ui` поднимают настоящий `QApplication` (без дисплея — `offscreen`). Qt привязан к главному потоку, а `go test` гоняет тесты в горутинах, поэтому `TestMain` крутит цикл событий, а тело теста идёт через `onMain` (`mainthread.Wait`). Внутри `onMain` нельзя `t.Fatal` — только `t.Error` и `return`. Сквозные тесты окна ходят в `mmfake` через `httptest`. `TestMain` применяет настоящую тему (`InitStyle`), поэтому раскладка в тестах как в жизни. `MATTERQUTE_TEST_SHOTS=<каталог>` — тесты сохраняют скриншоты окна в ключевых местах (`shot()`, `shotWidget()`), чтобы посмотреть глазами.

Разработка без настоящего сервера: `go run ./cmd/mmfake` (слушает `127.0.0.1:8065`; учётки `alice`/`secret` и `bob`/`secret` с MFA-кодом `123456`; `-crt disabled|default_off|default_on|always_on` — режим свёрнутых тредов, `-chatter 2s` — bob пишет в town-square).

Без дисплея: `QT_QPA_PLATFORM=offscreen MATTERQUTE_SCREENSHOT=/tmp/shot.png ./matterqute` — через 3 с (`MATTERQUTE_SCREENSHOT_DELAY`) сохраняет видимые окна в `/tmp/shot-N.png` и выходит. Конфиг подменяется через `XDG_CONFIG_HOME`. `MATTERQUTE_DEBUG=1` — debug-логи (в т.ч. все события WebSocket).

## Архитектура

| Пакет | Что делает | Qt |
|---|---|---|
| `internal/mm` | вход (логин/пароль/MFA), сессия, realtime по WebSocket с переподключением, режим CRT | нет |
| `internal/store` | состояние одного сервера: команды, каналы, членства (непрочитанные, упоминания), пользователи, загруженные ленты, треды (CRT) | нет |
| `internal/emoji` | имена эмодзи Mattermost ↔ символы (по `model.SystemEmojis`) | нет |
| `internal/status` | свой статус Mattermost и «не беспокоить»: стандартные статусы, сроки (до конца дня, недели…), истёк ли, подпись «до 15:30» | нет |
| `internal/complete` | автодополнение: слово под курсором (`@`, `#`/`~`, `:`) и подбор пользователей, каналов, эмодзи | нет |
| `internal/config` | список серверов в `os.UserConfigDir()/matterqute/config.json`; токены сессий — в системном keyring, без него — в `tokens.json` (0600) | нет |
| `internal/markdown` | текст поста → подмножество HTML для Qt rich text (goldmark + GFM, правила Mattermost), вложения интеграций (`props.attachments`); абзацы поля ввода с оформлением → markdown (`FromBlocks`) | нет |
| `internal/cache` | файлы сервера на диске (`~/.cache/matterqute/<хэш сервера>`): превью, вложения, кастомные эмодзи, аватары | нет |
| `internal/theme` | токены дизайна (`tokens.json` → `Palette` светлой и тёмной темы), QSS, SVG-иконки, шрифты — всё через `go:embed` | нет |
| `internal/qtx` | cgo-прослойка к тому, чего нет в MIQT: `QStyleHints::colorScheme` (Qt 6.5+) и её сигнал | да |
| `internal/ui` | виджеты MIQT: `Shell` (окно: меню, строка состояния, страницы), `App` (серверы: у каждого окно или страница входа), `LoginView`, `MainWindow` (сайдбар, лента, тред, поле ввода одного сервера), `Tray`, `style.go` (тема) | да |
| `internal/notify` | уведомления рабочего стола: org.freedesktop.Notifications по DBus (godbus), клик → «Открыть» с токеном активации; счётчик на значке в доке (`com.canonical.Unity.LauncherEntry`) | нет |
| `internal/desktop` | ярлык `matterqute.desktop` и иконки в `$XDG_DATA_HOME` (`--install`/`--uninstall`), обработчик ссылок `mattermost://` | нет |
| `internal/instance` | одно приложение на сессию: второй запуск отдаёт ссылку первому по DBus (`io.github.matterqute`) и выходит | нет |
| `internal/mmfake` | фейковый сервер для разработки и тестов | нет |
| `cmd/matterqute` | точка входа | да |
| `cmd/mmfake` | запуск `mmfake` на порту | нет |

### Статус

- Свой статус — `user.props.customStatus` (эмодзи, текст, срок `thirty_minutes`/`one_hour`/`four_hours`/`today`/`this_week`/`date_and_time`, `expires_at`): `PUT/DELETE /users/{id}/status/custom`; «сегодня» — до конца дня, «неделя» — до конца воскресенья (`status.ExpiresAt`). Истёкший не показываем (`status.Current`); раз в минуту перерисовываем, где он виден.
- Присутствие — `PUT /users/{id}/status`; «не беспокоить» со сроком — `dnd_end_time` в секундах («до завтра» — завтра в 9:00, как веб-клиент).
- Панель статуса — клик по `@user` в строке состояния или «Файл → Статус…»: свой статус и присутствие; окно своего статуса — эмодзи (то же окно выбора), текст, стандартные, срок. Чужие статусы — у имени автора в ленте, после имени в личке сайдбара (подсказка — текст и срок), в карточке. Обновляются по `user_updated`.

### Несколько серверов

- `App` держит список серверов в порядке `config.Servers`. У каждого, куда вошли, — свой `MainWindow` со своим WebSocket, уведомлениями и счётчиком; у остальных — страница входа (адрес и логин из настроек). На экране один, его URL — `config.Active`.
- При запуске входим по токенам на все серверы сразу; фоновый вход окно не переключает.
- Меню «Сервер» (решение 6d): текущий с галочкой, у остальных — счётчик упоминаний и непрочитанных личек, Ctrl+1…9; «•» у заголовка, если на неактивном сервере есть новое (цветную точку в заголовок строки меню Qt не нарисует). «Добавить сервер…» — пустая страница входа; уйти с неё — выбрать сервер в меню.
- Трей суммирует счётчики всех серверов (`MainWindow.OnCounts` → `Counts{Mentions, Unread}`). Клик по уведомлению сначала переключает на его сервер. В строке состояния — соединение показанного сервера.
- «Выйти из аккаунта» — только с текущего сервера: токен удаляется, сервер остаётся в списке со страницей входа. «Сервер → Удалить сервер…» (с подтверждением) — выход и сервер прочь из списка и `config.json`; на экране — следующий или страница добавления.
- Счётчик на значке в доке — сумма сообщений мне по серверам (`notify.Launcher`): сигнал `LauncherEntry.Update` для `application://matterqute.desktop`; док сопоставляет его со значком только при установленном ярлыке (`--install`).
- Ширины колонок общие: при переключении `MainWindow.SetColumns` подтягивает последние сохранённые.

### Потоки

- Окна создаются с `WA_DeleteOnClose`: после закрытия Go-обёртка указывает на удалённый C++-объект. Коллбеки из горутин перед обращением к виджетам проверяют, что окно живо (`MainWindow.closed`, `App.login != l`, флаг по сигналу `destroyed` у карточки пользователя).
- Qt-объекты трогаем только из главного потока Qt — того, где создан `QApplication` (MIQT сам делает `runtime.LockOSThread`).
- `mm` работает в своих горутинах и Qt не импортирует. `store` тоже без Qt, но однопоточный: им владеет главный поток. Сетевой запрос — в горутине, результат — в главный поток через `MainWindow.ui` (`mainthread.Start` + проверка, что окно живо), и только там меняем `store` и виджеты. Поэтому мьютексов нет.
- События WebSocket разбираются (JSON) в горутине `RunRealtime`, в главный поток уходит готовое действие (`decodeEvent` в `internal/ui/events.go`).
- После каждого (пере)подключения WebSocket (`RealtimeHandler.OnConnected`) состояние досинхронизируется по REST: события за время обрыва потеряны.

### Лента сообщений

Вся лента — один документ `QTextBrowser` (`Feed`): так выделение и копирование идут через любые сообщения. Каждый пост — свой `QTextFrame`; новые, изменённые и удалённые посты правятся точечно (`insert`/`render`/`Remove`), позиции остальных фреймов и выделение пользователя документ сдвигает сам. Историю подгружаем страницами по 60 при прокрутке к верху. Пока держим всё загруженное.

- Реакции, «+» и превью — картинки-ресурсы документа (`AddResource`, рисуем плашки сами через `QPainter`), клики по ним и по «Открыть/Сохранить/N ответов» — ссылки `mm-react:`, `mm-react-menu:`, `mm-thread:`, `mm-open:`, `mm-save:` (`Feed.onAnchor`); имена ресурсов только ASCII — документ сверяет их через `QUrl`.
- Между соседними фреймами Qt держит пустой абзац (и после таблицы внутри поста) — `Feed.squash` ужимает их до 1 px, иначе между сообщениями пустые строки.
- Переопределять виртуальные методы (`OnContextMenuEvent` и т. п.) — у самого `QTextBrowser`: через встроенный `QTextEdit` MIQT паникует («can only override virtual methods for directly constructed types»).
- При копировании из буфера убираем U+FFFC (заглушки картинок) и хвостовые пробелы (`copySelection`).
- Под сообщением в ленте канала или лички, из которого тред ещё не начат, на месте «N ответов» — ссылка «Ответить» (`mm-thread:`, `threadHTML`); у системных и в панели треда её нет. Кнопок при наведении нет: место кнопки у правого края поста оказалось неудобным. Пост под курсором (контекстное меню, `topPost`) — `postAtY` по геометрии фреймов (`frameBoundingRect`): `cursorForPosition` в верхнем поле поста отдаёт конец предыдущего.
- Места в ленте — из раскладки документа (`postTop`, `Feed.cursorRect`), перед этим `doc.Size()` (раскладка ленивая). `QTextEdit::cursorRect` после перерисовки с прокруткой из кода бывает сдвинут на старое смещение (у всех позиций поровну), а рисует и ищет под мышью Qt по новому: восстановление места в `edit()` по нему сдвигало ленту на эту разницу.

- Последние 60 сообщений всех каналов и личек грузятся заранее, в фоне (`preload`, по 3 одновременно): сначала каналы с непрочитанным, потом лички по свежести, потом остальные; ошибки — только в лог. Запускается после каждой загрузки сайдбара, значит, и после переподключения (ленты сброшены). Дальше ленты держит свежими WebSocket, открытие канала берёт готовую; более старое — подгрузкой при прокрутке.
- Пустая `store.Timeline` создаётся до запроса первой страницы, чтобы посты из WebSocket, пришедшие во время загрузки, не потерялись; `Loaded` — первая страница пришла.
- Свой пост приходит дважды — ответом на `CreatePost` и по WebSocket; дедупликация по id в `Timeline.Upsert` и `Feed.Upsert`.
- Свёрнутые треды (CRT): включены ли — решает `mm.CRTEnabled` так же, как веб-клиент (конфиг `CollapsedThreads` + настройка `display_settings/collapsed_reply_threads`; по умолчанию на сервере `always_on`). При CRT лента канала — только корни (`collapsedThreads=true`), непрочитанное канала — по `*_root`-счётчикам, ответы живут в панели треда, есть псевдо-канал «Треды» (`threadsID`) со списком подписок. Без CRT ответы идут в ленте канала с кнопкой «в треде».
- Режим CRT читаем в главном потоке до запуска горутины (`crt := m.st.CRT()`): `store` из горутин трогать нельзя.
- Панель треда держит свою `store.Timeline` (`threadView`), не в `store`. Один объект поста может лежать и в ленте канала, и в треде, поэтому перерисовываем по факту наличия поста, а не по «изменилось ли» (`ApplyReaction` возвращает пост и `changed` отдельно).
- Реакции: применяем по ответу сервера и по WebSocket; повтор ничего не меняет (`store.WithReaction`).
- При наведении на сообщение (в ленте канала и в панели треда, кроме системных) — панель реакций над его правым верхним углом (`quickBar`, `quickreact.go`): 10 недавних — как «Недавние» в окне выбора (`recent_emojis`, самые частые первыми; не хватает — из `emoji.Quick`), своя отмечена, клик ставит или снимает; последняя кнопка — окно выбора из всех. Виджеты в документ не встраиваются — это ребёнок viewport ленты, как ролики; пост под курсором — `postAtY`, место — `postTop`; после прокрутки и правок документа панель ищет пост под курсором заново (`follow`), уход мыши из ленты и выделение текста её прячут. Недавние с сервера грузятся при первом показе панели (`loadEmojiData`). Кнопки, добавленные в уже видимую панель, показываем сразу (`Show`): иначе Qt покажет их после событий, и размер панели посчитается без них.
- Выбор реакции — своё окно (`emojiPicker`), а не `QMenu`: «+» у реакций и «Реакция…» в контекстном меню. Поиск по всем именам (по символу одно имя, у 👍 — `+1`), разделы Unicode в порядке CLDR (`internal/emoji/groups_gen.go`, генератор — `internal/emoji/gen` по `emoji-test.txt`), «Недавние» и «Эмодзи сервера». Недавние — как у веб-клиента: настройка `recent_emojis` (имя — id пользователя, `[{name, usageCount}]`, до 27), общие с ним. Сетка — один виджет, рисуется видимая часть.
- Анимированные эмодзи сервера (GIF больше одного кадра): один `QMovie` на эмодзи на окно сервера (`Assets.EmojiMovie`), рисующие подписываются на кадры (`OnEmojiFrame`); без подписчиков `QMovie` стоит. В ленте эмодзи в тексте — ресурс документа `emoji:<имя>` (не `file://`: файл документ берёт первым кадром), плашка реакции помнит, как себя перерисовать (`pill.render`); при очистке ленты подписки снимаются. Окно выбора крутит их, пока открыто.
- Эмодзи в окнах и списках — картинками шрифта Noto Color Emoji (`emojiPixmapSized`), не текстом виджетов: шрифт меню и подписей выбирает система, и на ноуте в `QMenu` они были чёрно-белыми (в контейнере offscreen — цветные, причину не воспроизвести). В `QMenu` эмодзи не кладём.
- Селектор `fe0f` внутри составного эмодзи (через ZWJ) Qt 6.8 с Noto Color Emoji не собирает — 🏳️‍🌈 выходит флагом и радугой рядом; `emoji.Char` убирает его в таких последовательностях, у одиночных оставляет.

### Уведомления и трей

- Решает `store.ShouldNotify` по правилам веб-клиента (`notification_actions.tsx`): свои посты (кроме вебхуков), системные, заглушённые каналы, статус «не беспокоить» или «нет на работе» — молчат; уровень — `notify_props.desktop` канала, при `default` — профиля, без него — «все»; в группе «по умолчанию» при «упоминаниях» в профиле — «все»; на «упоминаниях» — только упоминания и лички; ответ при CRT — если упомянули или сервер включил нас в `followers` события `posted` (туда он кладёт только тех подписчиков треда, кому по `desktop` и `desktop_threads` положено уведомление). Новая личка, которой ещё нет в сайдбаре, уведомляет по `channel_type` из события.
- Окно не уведомляет, если оно активно и открыт этот канал (для ответа при CRT — этот тред). Пачка постов в одном канале или треде заменяет своё уведомление (`replaces_id`), а не копит их.
- Текст — `markdown.PlainText`; у пустого поста — текст вложения интеграции или имена файлов. Заголовок по дизайну: «bob в #backend», «bob в треде, #backend», в личке — «bob».
- Клик — `ActionInvoked` с ключом `default`; перед ним сервер уведомлений может прислать `ActivationToken`, его кладём в `XDG_ACTIVATION_TOKEN`: на Wayland Qt берёт его при активации окна (по коду qtwayland, на Wayland не проверено).
- `Notifier` создаёт `main`, а не `App`: тесты `App` не должны стучаться в настоящую сессионную шину. Тесты `notify` поднимают свой `dbus-daemon` с подделкой сервера уведомлений (без него — skip).
- Свой статус тоже запрашиваем (`/users/status/ids` вместе с собеседниками): без него не работает «не беспокоить».
- Новое уведомление при неактивном окне — ещё и `QApplication::alert`: значок окна на панели задач просит внимания.
- Трей (`Tray`) — только если он есть (`QSystemTrayIcon::isSystemTrayAvailable`; у GNOME без расширения AppIndicator и в offscreen его нет). Значок рисует код по макету (AppIcon «hash», режим mono): облачко во всю ширину, «#» вырезан насквозь. Есть сообщения мне (`store.Mentions`: упоминания по каналам, в личках сервер считает упоминанием каждое сообщение, плюс треды при CRT) — облачко красное, вместо «#» их число; иначе есть новые в незаглушённых каналах (`store.NewMessages`, при CRT — корни и ответы в подписанных тредах) — зелёное с их числом; больше 9 — «9+». Каждый размер (16…64) рисуется отдельно в физических пикселях, «#» — прямоугольниками по пиксельной сетке (масштабирование из 2× его размывало), цифры — Plex жирным с хинтингом по умолчанию (полный ломал форму, клетками «1» походила на «i»). Цвета и размер цифр — «Вид → Значок в трее…» (`config.json` → `tray`: `idle`, `unread`, `mentions`, `digits`); цвета пусто — цвет текста панели, зелёный значка приложения (`appGreen`) и `dang` темы чуть темнее; размер цифр — шрифт в % высоты значка (трей берёт значок 16…64 px, одно число пикселей подошло бы не всем), 0 — «авто», высотой со знак «#»; в любом случае число не выходит за облачко.
- Иконка приложения (окно, уведомления, ярлык `--install`) — то же облачко, зелёное с белой «#», без плитки из макета (`appIconPixmap`, `bubblePixmap`): плитка и «#» шрифтом в мелких размерах мылились; каждый размер — отдельно. Панель считаем тёмной у GNOME всегда, у остальных — по системной теме.
- С треем крестик прячет окно (`Shell.HideOnClose`), а не завершает приложение, — иначе уведомления перестанут приходить. «Выход» в меню и в трее — `Shell.Quit`: закрывает видимое окно (сохраняется его положение) и выходит.

### Разметка, файлы, ссылки

- Markdown рендерится в HTML, который понимает `QLabel`: `<pre>` не переносит строк — код идёт в ячейке таблицы с `white-space:pre-wrap`; у `<p>` обнуляем поля; `border-collapse` в Qt 6.8 прячет рамки таблиц — не использовать. Сырой HTML Mattermost показывает текстом — мы тоже. goldmark режет текст по `_ ~ *`, поэтому трансформер `mergeText` склеивает соседние текстовые узлы до поиска `@`, `~`, `:эмодзи:`.
- Ссылки в тексте не открываются сами: `mm-channel:`/`mm-user:` обрабатывает окно (`handleLink`); ссылки своего сервера (сообщение `/team/pl/id`, тред `/team/threads/id`, канал `/team/channels/name`, личка `/team/messages/@user`) — здесь же (`permalink.go`: `ownPath`, `openServerPath`), другого добавленного сервера — переключившись на него (`App.openOnOtherServer`); прочие http(s)/mailto — `QDesktopServices`, остальное игнорируется.
- Переход к сообщению (`goToPost`): его канал, прокрутка — верх поста на трети высоты ленты (`Feed.ScrollToPost`), подсветка на 4 с (`Feed.Highlight`, цвет `AccW`); нет в загруженной ленте — догружаются старые страницы, до 50 (`loadOlderUntil`). Ответ в треде — ещё и в панели треда, прокрученной к нему (`openThreadAt`); при CRT в ленте канала подсвечен корень.
- Ссылки из браузера: страница Mattermost «Открыть в приложении» ведёт на `mattermost://сервер/путь`; ярлык (`--install`) объявляет обработчик `x-scheme-handler/mattermost` (`Exec … %u`, `xdg-mime default`). Ссылку получает `main` аргументом; если приложение уже запущено, `instance.Claim` передаёт её первому по DBus вместе с `XDG_ACTIVATION_TOKEN` и выходит. `App.OpenLink`: окно наверх, через 150 мс (пусть оконный менеджер успеет отрисовать окно: на XFCE поднятое окно стояло пустым, пока шёл переход) — сервер ссылки на экран (ещё не вошли — путь откроется после входа, `server.pending`; сайдбар не загружен — после него, `MainWindow.pendingPath`), незнакомый сервер — страница добавления с его адресом. Второй запуск без ссылки просто поднимает окно.
- Картинки и эмодзи: `Assets` (главный поток) отдаёт то, что уже в `cache`, и догружает остальное; лента перерисовывается одним проходом (`Feed.refreshSoon`). Пока превью грузится, на его месте серая заглушка того же размера из `FileInfo`, чтобы лента не прыгала.
- Посты вебхуков Mattermost пишет от создателя вебхука (`user_id`), а имя и иконку интеграции кладёт в props (`override_username`, `override_icon_url`), только если сервер разрешает подмену. Имя, аватар, ссылка и карточка такого поста — интеграции (`store.PostIntegration`, `showIntegrationCard`), создатель — ссылкой из карточки, как в веб-клиенте. Склейка подряд идущих сообщений — по показанному автору (`sameAuthor`). Иконку качаем со стороннего адреса без токена Mattermost, до 1 МБ и только картинку (`cache.FetchIcon`); прокси картинок сервера (`HasImageProxy`) не поддержан.
- Предпросмотр ссылок: данные добывает сервер и кладёт в `post.metadata.embeds` (`store.PostPreviews`): `opengraph` — карточка (сайт, заголовок-ссылка, описание, картинка до 492×260), `image` — картинка по ссылке (размер из `metadata.images`, как у вложений), `permalink` — карточка с автором, каналом, началом текста и «Перейти к сообщению» (`mm-permalink:`: канал и прокрутка к посту, если он в загруженной ленте). Выключено пользователем (`display_settings/link_previews`) — только ссылки на сообщения; автор может убрать предпросмотр у своего поста (свойство `remove_link_preview` через `PatchPost`, как веб-клиент). Картинки — `cache.FetchLinkImage`: чужой сервер без токена, сам сервер (прокси картинок) — с токеном; до 10 МБ, только картинка.
- Клик по картинке (вложение или картинка по ссылке) — просмотр во весь экран внутри приложения (`imageViewer`, `MainWindow.openImage`): сначала превью из кэша, потом оригинал (`Assets.Download`, для ссылок — `LinkImage`), с поворотом по EXIF, GIF — `QMovie`. Вписана в экран, мелкая — в своём размере; колесо и +/− — масштаб у курсора, двойной клик или 1 — 1:1, 0 — по экрану, перетаскивание — сдвиг, ←/→ — картинки того же поста, Esc, клик по фону или ✕ — закрыть. Сверху — «Сохранить…» и «Открыть в приложении» (тип из белого списка) или «Открыть в браузере». Ссылка на картинку по ссылке — `mm-linkimg:<пост>:<N>`: N-я среди картинок по ссылкам поста.
- Имена файлов и эмодзи — от других пользователей: на диск только через `cache.SafeName` и проверку имени/id. «Открыть» системным приложением — только типы из белого списка (`canOpen`); `.desktop`, скрипты, HTML, SVG — только «Сохранить…».
- Автодополнение в поле ввода: `complete.At` по тексту строки до курсора решает, что дополнять (`@` — пользователи и `@here`/`@channel`/`@all`, `#` и `~` — каналы, вставляется `~имя`, `:` — эмодзи с двух символов; только с начала слова). Сначала показываем известное клиенту, через 150 мс после паузы в наборе — вместе с ответом сервера (`/users/autocomplete` — участники канала первыми, `/teams/{id}/channels/autocomplete`, `/emoji/autocomplete`); ответы для уже другого слова отбрасываются. Список — `QFrame` в окне поля ввода, фокус не берёт: стрелки, Enter, Tab и Esc перехватывает поле. Esc не даёт открыть список снова для того же слова.
- Поле ввода — с оформлением (WYSIWYG, `richedit.go`, `formatbar.go`): жирный, курсив, зачёркнутый, код, ссылки, списки (с вложенностью), цитаты, блоки кода — на экране без markdown-символов. Документ читается абзацами (`readBlocks` → `markdown.Block`/`Span`) и уходит markdown'ом Mattermost (`markdown.FromBlocks`); обычный текст — как есть, без экранирования: набранная руками разметка работает, как в простом поле. Что чем оформлено, отмечают свойства форматов (`propCode`, `propQuote`, `propCodeBlock`); форматы в документе всегда из `spanFormat`/`blockFormat`, других `readBlocks` не понимает. Вставка — простым текстом (`acceptRichText=false`).
- Ввод: Enter — отправить, Shift+Enter — новая строка (в списке — пункт, в цитате — строка цитаты; на пустой — выход), в блоке кода Enter — новая строка, на пустой последней — выход, Ctrl+Enter — отправить всегда; Tab/Shift+Tab — уровень пункта; Backspace в начале цитаты, кода, пункта — обычная строка. Markdown при наборе превращается в оформление: `**…**`, `__…__`, `*…*`, `_…_` (не внутри слова), `~~…~~`, `` `…` `` — по закрывающему символу; `- `, `* `, `1. `, `> `, ` ``` ` в начале строки — список, цитата, блок кода; Ctrl+Z возвращает набранное. Сочетания: Ctrl+B, Ctrl+I, Ctrl+Shift+X, Ctrl+Shift+C (код), Ctrl+K (ссылка: окно «Текст»/«Адрес», без схемы — https://), Ctrl+Shift+8/7/9 (списки, цитата), Ctrl+Alt+Shift+C (блок кода). Панель кнопок над полем — кнопкой «Aa» (во всех полях сразу, `config.json` → `format_bar`).
- Полосу цитаты рисует `paintQuotes` поверх viewport (у формата абзаца рамок нет); прямоугольник абзаца из раскладки начинается до его отступа. Цвета и шрифты оформления записаны в документ: при смене темы или моноширинного шрифта поле перерисовывается из абзацев (история правок сбрасывается). Подсказку пустого поля Qt рисует, пока в документе нет текста, — и поверх пустого пункта «1.», цитаты, блока кода; тогда её убираем (`updatePlaceholder`).
- Правка и удаление своих сообщений (`postedit.go`): «Изменить» и «Удалить…» в контекстном меню (правка — не у системных и не у вебхуков), ↑ в пустом поле — правка последнего своего в этой колонке. Правка — в поле ввода той же колонки (канал или тред), с оформлением: `markdown.ToBlocks` разбирает сообщение в абзацы редактора, то, чего редактор не умеет (заголовки, таблицы, картинки, HTML, код с языком), остаётся исходным текстом — сохранённое без изменений сообщение не меняется (тест `TestToBlocksRoundTrip`). На время правки черновик откладывается (`StartEdit`/`CancelEdit`), над полем — плашка «Редактирование», Enter сохраняет (`PatchPost`), Esc отменяет, стёртый текст — вопрос об удалении. Удаление — с подтверждением (красная кнопка, `danger`); сервер удаляет корень вместе с ответами. Удаление приходит и ответом, и по WebSocket — `store.ApplyDeleted` применяет его один раз и уменьшает счётчик ответов корня.
- Код и ссылка в поле ввода не тянутся дальше при переходе курсором в их конец (`leaveCodeAndLink`): набор там — обычным текстом; при наборе подряд (включил код и печатаешь) — не трогаем.
- Слэш-команды (`commands.go`): сообщение, первая строка которого начинается с «/» (не «//»), без файлов, — команда: `/commands/execute` с `channel_id`, `team_id` (у личек — первая команда) и в треде `root_id`. Ответ «только вам» сервер шлёт событием `ephemeral_message` — в ленту канала и треда без счётчиков непрочитанного (тип `system_ephemeral`, с разметкой и пометкой «Видно только вам»), до перезагрузки ленты; `goto_location` из ответа — переход (`gotoLocation`: канал своего сервера — открыть, после `/join` — через перезагрузку сайдбара; личка; ссылка на сообщение; чужое — в браузере). Ошибка — текстом сервера под полем, команда — снова в поле. Команды нет на сервере — она снова в поле, и следующий Enter отправит её обычным сообщением (`OfferAsText`). Подсказки по «/» — с сервера (`/teams/{id}/commands/autocomplete_suggestions`): имена команд, а после пробела — аргументы (каналы для `/join` и т. п.).
- Черновики поля ввода — по каналу (и по треду в панели): `Composer.SwitchTo`, хранятся абзацами с оформлением; неудачная отправка возвращается в черновик своего канала, даже если пользователь уже ушёл.
- Логику держим вне виджетов (`store`, `markdown`), чтобы перерисовка UI её не трогала.

### Внешний вид

Дизайн — `docs/design_handoff_matterqute` (Claude Design): `README.md` — размеры и состояния всех элементов, `feed-html.md` — HTML ленты, `tokens.json`, `qss/`, `icons/`, макеты в `design/*.dc.html` (открываются в браузере). Рабочие копии токенов, QSS и иконок лежат в `internal/theme`; правим там, handoff — эталон для сверки.

- Тема: «Вид → Тема» (системная, светлая, тёмная), выбор — в `config.json` (`theme`). Системная следит за `QStyleHints::colorScheme` через `internal/qtx`. `applyTheme` ставит `QPalette` и QSS приложения и зовёт подписчиков `OnThemeChanged`: виджеты с цветами в коде (иконки, делегаты, HTML ленты) перерисовываются сами. Отписка — функция, которую вернул `OnThemeChanged`, при закрытии виджета.
- Окно и колонки запоминаются в `config.json` (`window`): место, размер и «развёрнуто» — `QWidget::saveGeometry` при закрытии окна (поэтому «Выход» закрывает окно, а не зовёт `QCoreApplication::quit` мимо `closeEvent`); ширины сайдбара и панели треда — числами, через 500 мс после перетаскивания разделителя. Ширину скрытой панели треда помнит сам `QSplitter`. На Wayland место окна выбирает композитор — восстанавливаются только размер и «развёрнуто».
- Шрифты — «Вид → Шрифты…» (`fonts.go`): сайдбар, лента с полем ввода, моноширинный (код, время); `config.json` → `fonts`, пусто — по дизайну (Plex 14, Plex 14, PT Mono 13). Применяются сразу через подписчиков `OnThemeChanged`. HTML ленты пишется в пикселях макета, а `scaleFonts` при вставке в документ пересчитывает `font-size` под размер ленты и подменяет `'PT Mono'` выбранным моноширинным — одно место вместо правки каждой строки. Высота строки сайдбара растёт со шрифтом (`DoItemsLayout`). Плейсхолдер поля ввода Qt рисует шрифтом viewport — ему тоже задаём.
- Цвета берём только из `Pal()` (текущая палитра), не хардкодим. Иконки — `iconPixmap(name, color, size)`: SVG из `theme`, `currentColor` заменяется цветом, рендер в 2× для HiDPI.
- Свойства для QSS — `setProp` + `repolish` (QSS не перечитывает динамические свойства сам). `objectName` — через `setName`: в MIQT `SetObjectName` принимает `QAnyStringView`.
- Сайдбар и список тредов — `QTreeWidget`/`QListWidget` без текста в элементах, всё рисует делегат (`paintSidebarRow`, `paintThreadRow`); фон наведения и выбора — QSS. Первая строка корня в списке тредов — с оформлением: `markdown.PreviewLine` (без маркеров списка, цитаты, заголовка; из блока кода — первая строка кода) рисуется `QTextDocument` в одну строку (`drawRichLine`), не влезает — обрезана с «…» (`richLineDoc`).
- Аватары: фото с сервера (если `LastPictureUpdate > 0`, кэш на диске) или инициалы на цвете по хэшу username (`theme.Palette.Avatar`; у ботов свой цвет). Статусы — из `/users/status/ids` и событий `status_change`.
- Всплывающие карточки (пользователь, интеграция, панель статуса) — `Qt::Popup` с `QFrame#userCard` внутри, окно ровно по карточке; углы скругляет маска окна (`card.roundCorners`), не `WA_TranslucentBackground`: без композитора (X11) прозрачное рисуется чёрным. Место — `card.place`: ниже-правее точки, не помещается — выше, всегда в пределах экрана; панель статуса — над своим именем в строке состояния (и из меню «Файл»).

Rich text в Qt 6.8 (проверено на скриншотах):

- `nowrap` игнорируется — ширину подписи в ячейке задаём явно по `QFontMetrics` (разделители дней и «N ответов»).
- Высота пустой ячейки не соблюдается — линию в 1 px рисуем ячейкой с `bgcolor` и `font-size:1px`.
- `width="520"` у таблицы внутри ячейки поста игнорируется, таблица растягивается на всю ленту; ширину держит `<td width="520">` внешней таблицы с пустой соседней ячейкой (вложения интеграций).
- Картинки в ленте не увеличиваются, не шире колонки текста и не выше 400 px (`imageSize`); при изменении ширины ленты посты с картинками и видео перерисовываются. GIF крутит `QMovie`, кадры подменяются в ресурсе документа.
- Видео: Mattermost превью для роликов не делает, поэтому ролик до 20 МБ лента качает сама и разбирает (`probeVideo`: `QMediaPlayer` без звука + `QVideoSink` до первого кадра) — кадр, длительность и размер ложатся в кэш (`cache.Video`, всё в имени PNG). Превью — кадр, кнопка 48 px, длительность; пока не разобран — тёмный 16:9 и размер файла.
- Ролик играет прямо в ленте (`inlineVideo`): клик по превью (`mm-video:`) — пуск, повторный — пауза. Виджеты в `QTextDocument` не встраиваются, поэтому это виджет-ребёнок viewport ленты поверх картинки превью: место ищем по символу картинки (U+FFFC с именем `video:<id>:…`) и `Feed.cursorRect`, двигаем при прокрутке, ресайзе и после правок документа (`placeVideos`). Кадры рисуем сами из `QVideoSink` — обычный виджет честно обрезается краем ленты. `QTextCursor::charFormat` в начале блока возвращает формат символа после курсора — поэтому сверяем сам символ. В ленте играет один ролик; при очистке ленты ролики останавливаются.
- «Во весь экран» — только отдельной кнопкой: окно `player` с `QVideoWidget` и панелью по макету, с той же позиции; Esc или та же кнопка закрывают его, и ролик продолжается в ленте. Окно — с родителем `MainWindow`: закрывается вместе с ним и не держит приложение.

## Соглашения

- Ошибка содержит данные, из-за которых отказали: URL сервера, операцию, HTTP-статус, id ошибки Mattermost (см. `mm.ServerError`). Пароли и токены в сообщения и логи не попадают.
- Таймстампы в логах — `YYYY-MM-DD HH:MM:SS`, местное время.
